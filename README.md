# Playable LP 制作運用

- 各案件を `projects/<案件ID>/` に分離する。既存案件や参照元を上書きしない。
- 着手前に brief.md と status.json を読む。参照URL、目的、訴求、素材、CTA、未確認情報を記録する。
- 企画 → 制作 → QA → 修正 → 再QA → プレビュー提出を実施する。未検証を合格と記載しない。
- 操作はタッチ、マウス、キーボードに対応。開始は明示操作、スキップ・再挑戦を用意。ズームを禁止しない。
- ゲーム操作領域はテキスト選択・画像のネイティブドラッグを防止する。親LPとiframe内の両方を対象とし、連続タップ・長押し・領域境界をまたぐドラッグで青い選択表示が出ないか検証する。商品説明やフォームの通常の選択・コピー、キーボードフォーカス、ズームは維持する。
- 動作合否に加え、操作性・思わず遊びたくなる楽しさ・デザイン品質を確認する。案件ごとに有名企業のブラウザゲーム、Playable Factory事例、現行ストア上位ゲームから近い体験を選び、実操作・観察・未検証を区別して改善点を記録する。
- 参照調査は入口の分かりやすさ、初回操作への反応、直接操作の追従、成功演出、難易度、再挑戦、視覚階層、余白、文字、素材の一貫性を比較する。元体験を簡易ボタンへ劣化させない。採用/不採用の理由を残す。
- ストア順位は国・カテゴリ・確認日を記録し、タイトルの本編と広告Playableを区別する。ソースは公開・提供されているものを読み、URL/コミット/確認箇所を記録する。非公開ソースを確認済みとしない。再利用時はライセンスを確認する。
- 価格・契約・配送・効能は現行の公式情報で確認してから掲載。根拠がなければ省く。
- 工程や修正が完了するたび status.json と journal.md を更新。問題は qa/report.md に再現手順・原因・修正・再検証結果を残す。
- Chromeで正常完走、途中スキップ、再挑戦、キーボード、モバイル幅、CTA、画像、横はみ出し、コンソールを検証する。
- 自己修正は再現 → 原因特定 → 最小修正 → 同じケースを再検証。3回連続で同じ問題が解決しなければ記録し、他の独立作業を進める。
- GitHub公開や接続未確認、外部依存は明示。認証情報をファイルやログに保存しない。
- 常駐・定期実行は設定が実際に完了した場合だけ稼働中と報告する。


# ゲーム品質の確認・改善基準

この基準は今後の制作の前提。元体験の復元を最低線とし、動作確認だけで完成としない。改善の採用には操作前後の比較を添える。

## 誤選択を防ぐ

- 親LPのプレイ領域とiframe内のゲーム領域に user-select:none / -webkit-user-select:none。
- ゲーム画像の標準ドラッグを防止。selectstart/dragstartも対象領域だけで抑制。
- 装飾の進捗・指示・台詞はpointer-events:noneにして、操作対象へ入力を通す。
- 商品説明、フォームの選択・コピー、Tabのフォーカス表示、ピンチズームを維持。
- QA: ダブル/連続クリック、スワイプ往復、長押し、領域をまたぐドラッグ、画像つかみ、再挑戦、商品文の選択。端末/ブラウザと証跡を記録。

## 3つの品質軸

| 軸 | 確認すること | 今回の改善候補 |
| --- | --- | --- |
| 操作性 | 操作対象と当たり判定が一致、指で隠れても状態が分かる、ドラッグ追従、領域外で離す/キャンセル/復帰が安全、連続入力が欠落しない | 拡大描画と骨の当たり判定のずれを測定。味付け適量の視認性と停止感を実機で比較 |
| 思わずプレイする楽しさ | 入口で触り方が分かる、最初の一手から変化、努力に比例する反応、成功を実感、失敗しても再挑戦が速い | 開始導線の長い説明より「魚をこする」体験を予告する案。操作直後の光/揺れ/音を確認。難しすぎる長押しの調整は元版との比較後に判断 |
| デザイン品質 | 主役/操作対象/指示の優先順位、余白と文字サイズ、色と光源の統一、素材品質、手やヒントの重なり、完了から商品の自然な接続 | 魚・鍋のリアル素材とUIの質感を揃える。画面端の情報密度、ヒントと進捗の競合を390/320pxで確認 |

初回理解時間、入力から視覚反応までの時間、誤操作数、完走時間、再挑戦数は、実測した場合のみ数値を記載。再プレイ意欲は観察/ユーザー感想と実測を区別。広告のCV改善は計測なしに断定しない。

## 自己修正

1. 公開用パッケージのゲームが開始しない。
   - 再現: releaseを4174で開くと、ステータスが空。consoleに Identifier '$' has already been declared。

2. 開始前スキップ後の再挑戦で開始画面が残る可能性、工程遷移中の再挑戦で古いタイマーが残る。
   - 原因: 元のretryはゲーム終了後だけを想定。
   - 修正: 開始画面、進行タイマー、pointer/pourに関係する状態を初期化。画面離脱時のpourと火キープを停止。
   - 再検証: 開始前スキップ→商品側再挑戦→工程1、overlay0件。完成後の再挑戦も確認。
3. 家族の台詞が操作ヒントと重なる。
